# ECS vs EKS 比較レポート（様式）

このファイルは**比較レポートの様式**です。採用結論や個人の記録は書きません。観察結果・採用判断・反対案は学習ポータルに記録し、このファイルの枠を使って整理します。**EKS を採用することを正解として扱いません**（ECS が適する条件も同じ重さで検討します）。

## 1. 課題シナリオ（仮定。ユーザー要件ではない）

> 月間数十万リクエスト規模の社内タスク管理サービスを AWS で運用する。少人数の運用チームが担当し、可用性・変更容易性・コスト・学習負担をバランスさせる。将来は別チームの複数サービスが追加される可能性がある。

これは比較の出発点として置いた仮定であり、実在の組織の要件ではありません。

## 2. 前提条件の書き方

シナリオの曖昧な点を、自分で決めた**仮定**として明示します。決めていない点は「未定」と書き、それが結論にどう影響するかも書きます。

| 項目 | 書く内容（例の観点） |
| --- | --- |
| 負荷 | ピーク時のリクエスト数の見込み、増減の傾向 |
| 可用性目標 | 許容する停止時間、AZ 障害の扱い |
| 運用体制 | 人数、Kubernetes または ECS の経験、当番の有無 |
| 将来の拡張 | 追加サービスの数、チームの数、共通基盤の要否 |
| 既存技術 | 既に使っているツール（CI/CD、監視、IaC） |
| 制約 | コスト上限、コンプライアンス、移植性の要求 |
